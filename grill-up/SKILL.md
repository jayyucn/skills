# grill-up — 向上拷问

## 使命

**先确认是不是正确的问题，再决定如何解决。** 将原始诉求视为待验证假设，而不是预设用户错误，也不将其直接当成最终需求。

**最小充分需求**：不预设具体方案、具备可验证的成功条件、包含必要约束，且足以指导下一步决策的目标。不是无法继续追问的终极动机。

## 职责与分工

- **grill-up**：事实核查、目标溯源、目标冲突识别、需求验证与锚定。
- **grilling**：基于已确认的目标与约束，压测方案、边界和取舍。
- 不越界进行完整方案设计，不替用户决定价值偏好，不为追问而追问。

## 执行流程

### 0. 分流

根据歧义、前提风险、影响范围与执行成本选择深度：

- **快速放行**：目标明确、低风险、易撤销、无明显错误前提；直接执行或交下游。
- **轻量拷问**：局部歧义或可疑前提；只查关键疑点，必要时问一个问题。
- **完整拷问**：架构/长期行为受影响、方案先行、归因存疑、目标冲突、潜在返工大或依赖历史载体；进入下述阶段。

### 1. 核查前提

先把诉求拆成：**观察 O、解释 I、目标 G、约束 C、方案 S**。观察需要证据，解释需要因果核查，方案不是目标。

优先核查足以推翻或缩小诉求的前提：功能是否已实现、历史断言是否过期、现象能否复现、归因是否成立、是否遗漏隐含约束。结果标记 **已证实 / 已证伪 / 未验证 / 存在争议**；未复现不等于证伪。代码任务尽量给出路径、行号、测试或提交证据。前提被推翻时重新评估剩余需求，不机械继续 Why。

具体取证优先级与案例见 [references/fact-check.md](references/fact-check.md)。

### 2. 向上溯源

用 **XY Problem + JTBD + Why/How 双向阶梯**：

1. 分开“用户提出的实现手段 X”与“希望达成的结果 Y”。
2. 追问“为什么需要它 / 它要完成什么工作”，每一步提升目标层级。
3. 用“如果不采用 X，是否仍能实现 Y”反向检验。
4. 允许目标分叉：区分并列目标、从属目标、冲突目标；保留硬约束与软偏好。
5. 在目标具有决策价值时停止，不追到空泛的终极动机。

详细阶梯方法与示例见 [references/laddering.md](references/laddering.md)。

### 3. 收敛验证

候选需求通过四项检查：

- **目标独立性**：是否摆脱非必要的具体实现方式？存在真实硬约束时不强行寻找替代方案。
- **结果可验证性**：能否用行为、状态、指标或明确的定性验收条件判断成功？不编造指标。
- **约束完整性**：其他方案即使达到目标，是否仍可能违反重要硬约束？
- **决策充分性**：是否足以排除明显不合适的方案、指导下一步决策？

达到决策充分性就停止；抽象程度更高不一定更有价值。

### 4. 锚定与交接

简洁产出：**原始诉求、关键事实状态、最小充分需求、关键约束、成功条件、方案状态、未决问题**。简单任务可以只用一句话。

当锚点实质改变原始诉求或影响重大决策时，向用户确认（确认并锚定〔推荐〕 / 需要修正 / 重新溯源）。不把代理推断当成用户已确认意图。将已确认锚点与未决事项交给 grilling 或执行阶段。

跨会话任务按需回写权威载体，保留历史证据，遵守权限与安全写入要求。详见 [references/persistence.md](references/persistence.md)。

## 交互原则

- **事实自己查，价值判断问用户**。不把能从仓库、文档、测试获取的事实推给用户。
- 一次只问当前最有决策价值的问题；已知信息不重复问。
- 有 AskUserQuestion 时，适合选择题才使用；推荐项排第一并标注“(推荐)”，允许自定义回答。不可用时用自然语言提问。
- 用户自定义答复修正锚点时，废弃旧选项；解释唯一则采用，关键歧义才继续问。
- “A 有代价、B 也有代价”是约束和犹豫，不是选择；先取证、寻找第三方案，再请用户权衡。估计必须标注，不伪称实测。
- 用户要求跳过或停止，立即放行；未确认内容标记为工作假设。高风险操作仍遵守必要授权与安全确认。

完整交互边界与逃生阀见 [references/interaction.md](references/interaction.md)。

## 反模式

不预设用户错误；不无条件拷问；不把解释当事实；不强行单链收敛；不无限追问 Why；不忽略约束；不伪造替代方案或证据；不重复确认；不替用户裁定偏好；不为形式而回写；不越界设计方案。

**最终准则：先证伪前提，再溯源目标；先区分约束，再检验需求；达到决策充分性就停止。**

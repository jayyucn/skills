# 目标溯源与收敛指南

## XY Problem + JTBD

“怎么实现 X”可能是手段，真正工作是达成 Y。问：“不采用 X，你真正希望获得什么结果？”但不要预设所有具体方案都是伪需求：有些是已确认的外部约束。

## Why / How 双向阶梯

- Why：从功能/动作向上寻找其服务的结果，每一步提高目标层级。
- How：反向检查该结果是否真的要求原始手段；检查有没有偷换概念。
- 不强求一条链：多个目标可以并列、从属或冲突。
- 分清目标、硬约束、软偏好、候选方案。不要把“尽量少点击”写成“绝不能增加点击”。

### 示例：导出 Excel

“给后台加导出 Excel 按钮” → 让负责人拿到报表 → 定期掌握关键指标 → 及时发现业务异常。

可能的最小充分需求：“负责人每周能可靠获取指定指标，并及时识别异常。”

反向校验：定时邮件或看板可能满足结果，按钮不是必需；但若外部流程强制接收 Excel 文件，则文件格式是硬约束，不能随意排除。

不要继续追到“帮助公司生存”等虽抽象却无法指导当前设计的终极目标。

### 示例：界面简化

“移除优先级图标”可能同时服务于：减少视觉噪声、提高编辑效率、保持优先级可见。

这些目标可能冲突；不要擅自把其中之一选作唯一“本质”。先标出硬约束与可权衡偏好，必要时交给用户裁定。

## 四项收敛检验

1. 目标独立：不依赖非必要的具体方案。
2. 结果可验：行为、状态、可测指标或清晰的定性标准。
3. 约束完整：替代方案不能以违反重要约束为代价。
4. 决策充分：能够筛除明显不合适的方案并指导后续决策。

四项满足即停止。若继续追问不会改变决策，也停止。反证是校验手段，不是必须证明存在某个替代方案。
